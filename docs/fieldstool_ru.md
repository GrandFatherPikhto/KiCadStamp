# fieldstool — массовая простановка/переименование Role/Cluster в `.kicad_sch`

«fieldstool» — имя небольшого семейства инструментов правки `.kicad_sch`-текста на одной общей
библиотеке, но больше не Python-пакет (влит в `kicadstamp`/`gui` 02.08.2026, см. [Где теперь лежит
код](#где-теперь-лежит-код) ниже):

- **`fieldstool_cli.py`** — офлайн CLI (подкоманды `set`/`rename`).
- **Таб fieldstool** — `gui.fieldstool_window.MainWindow`, встроен первым табом в основной
  [PyQt6 GUI](./gui_ru.md) (`gui/docks/fieldstool_dock.py`, см. [раздел про таб fieldstool в
  gui_ru.md](./gui_ru.md#таб-fieldstool)) — единственный способ его запустить (отдельный вход
  `fieldstool_gui.py` существовал с 01.08.2026 по 02.08.2026, удалён как чистое дублирование
  встроенного таба).

Оба правят `.kicad_sch` **напрямую, текстом** — не через живой IPC KiCad — потому что кастомные
поля `Role`/`Cluster` живут в схемном символе, а PCB-only запись через IPC тихо затирается
собственным «Update PCB from Schematic» KiCad (в основном GUI такая дока раньше и была —
`BulkFieldEditorDock`, удалена, её место занял fieldstool).

## Где теперь лежит код

Изначально свои пакеты `fieldstool`/`fieldstool.gui`, не зависящие от `kicadstamp`/`gui`. Разнесены
02.08.2026 по тому же водоразделу, что уже был в каждом модуле, когда выяснилось, что
`fieldstool.gui` на практике неотделим от `gui/` (всегда требует инжектированный
`gui.connection.BoardConnection`, встраивается исключительно через `gui/docks/fieldstool_dock.py` —
реальной независимости сохранять было нечего):

- **Библиотека правки схемы → в `kicadstamp/`, плоско, с префиксом `schematic_`** (не подпакет —
  `kicadstamp/` и так держит модули этого уровня плоско): `schematic_blocks.py` (побайтовый поиск
  диапазонов в тексте `.kicad_sch`), `schematic_discovery.py` (`walk_schematic_hierarchy()`),
  `schematic_safety.py` (проверка не-ASCII, `list_kicad_pids()`), `schematic_editing.py`
  (`apply_edits()`, пайплайн записи `.bak`/самопроверка), `schematic_config.py` (общий
  `load_fields_config()` — формат YAML-конфига, который читают и `set`, и `rename`),
  `schematic_set_fields.py`/`schematic_rename_fields.py` (логика планирования `set`/`rename`).
  `FieldsToolError` переехал
  прямо в `kicadstamp/exceptions.py` (обычный подкласс `Exception`, НЕ подкласс `PlacerError` —
  другой домен риска, перехват одного не должен случайно проглатывать другое). **`fieldstool_cli.py`
  использует это напрямую** и остаётся отдельным CLI/интерфейсом от `kicadstamp_cli.py` — разные
  домены (массовая правка текста схемы vs. расстановка на плате), тащить в один парсер аргументов
  не стоит.
- **Только-GUI куски → в `gui/`, плоско**: `gui/schema_model.py` (`load_schematic_components()` —
  схлопывает схему в одну строку на refdes для дерева компонентов; `fieldstool_cli.py` этот
  по-refdes-вид никогда не нужен), `gui/fieldstool_window.py` (`MainWindow`, встроенный табом
  fieldstool — см. [Таб fieldstool](#таб-fieldstool) ниже), `gui/docks/pending.py`
  (`compute_pending_edits()` + `PendingChangesDock` — это `QDockWidget`, разделяемый с остальными
  `gui/docks/`, прилеплен табом к Log внизу главного окна). Собственный файл настроек
  (`gui/fieldstool_gui_state.json`) переиспользует класс `Settings` из `gui/settings.py` с другим
  путём, а не второй почти идентичный модуль настроек.

Поведение при этом не изменилось — чистый перенос-переименование, та же логика, те же тесты
(перенесены вместе с кодом).

## Почему эта зона записи остаётся отдельной от `kicadstamp`/`gui`

Речь про принципиально другую зону записи, не про границы пакетов/процессов — их больше нет:

- **Принципиально другая, более рискованная зона записи.** `kicadstamp`/`gui` пишут только через
  живой транзакционный IPC KiCad (`BeginCommit`/`UpdateItems`/`EndCommit` — с undo самого KiCad).
  `schematic_editing.py` правит `.kicad_sch` как файл, напрямую — тот же класс риска, что баг KiCad
  #24966 (правка файла, который KiCad, возможно, держит открытым/закешированным), но хуже — тут
  вообще нет живого IPC KiCad.
- **KiCad должен быть закрыт для применения, и переоткрыт, чтобы увидеть результат.** Работающий
  процесс KiCad не подхватывает изменённый извне файл схемы «на лету». Проверено исчерпывающе (kipy
  0.7.1): в `kipy.KiCad`, `kipy.Board`, `kipy.Schematic` и во всех определениях proto-команд **нет
  вообще никакого способа программно закрыть KiCad или проверить «есть ли несохранённые
  изменения»**. Значит, кнопка «закрыть KiCad» может быть только **инструкцией** пользователю
  («закрой KiCad, потом жми Apply») — никогда не автоматизацией.
- **Точечная правка, не parse→dump.** Правки — точечная подстановка текста (regex + баланс скобок
  для границ блоков), никогда не полный цикл `sexpdata` parse→`dumps()` — нет прецедента, что
  `sexpdata.dumps()` воспроизводит форматирование самого KiCad побайтово. `sexpdata` используется
  только для **самопроверки** результата после записи (см. [Страховки](#страховки)).

## `fieldstool_cli.py`

```bash
python fieldstool_cli.py set roles.yaml [--write] [--allow-non-ascii] [--force-with-kicad-running] [--verbose]
python fieldstool_cli.py rename renames.yaml [--write] [--allow-non-ascii] [--force-with-kicad-running] [--verbose]
```

Оба подкоманды по умолчанию dry-run (печатают, что изменится, ничего не трогают); `--write`
обязателен, чтобы реально что-то поправить.

### `set` — refdes → `{field: value}`

```yaml
root_sheet: ../test_boards/3CH-AWG-TIA/3CH-AWG-TIA.kicad_sch   # КОРНЕВОЙ лист проекта, не папка
fields:
  C51:
    Role: C_OUT_BULK
    Cluster: FPGA_PWR_BANK/17
  C52:
    Role: C_OUT_BULK
    Cluster: FPGA_PWR_BANK/26
```

`root_sheet:` обходится рекурсивно (ссылки `(sheet (property "Sheetfile" "...") ...)`, безопасно
при ромбах/циклах), чтобы найти каждый достижимый `.kicad_sch` — не плоский glob по директории, так
что случайный посторонний `.kicad_sch` в той же папке никогда не попадёт в обработку по ошибке.

Два способа, которыми один refdes встречается в файле, оба учтены:
- **Многоюнитовый символ** (например, сдвоенный ОУ) — один refdes сидит в нескольких отдельных
  `(symbol ...)` блоках (по одному на unit); правятся все.
- **Многократный инстанс одного листа** (например, `Channel_1`/`2`/`3`, все — инстансы одного
  `channel_tpl.kicad_sch`) — несколько refdes делят ОДИН `(symbol ...)` блок, поле общее для всех
  них. Если конфиг просит **разные** значения для двух таких refdes — формат физически не может
  это выразить: фатальный отказ, а не молчаливый выбор одного из двух.

### `rename` — `field → {old_value: new_value}`, без refdes

```yaml
root_sheet: ../test_boards/3CH-AWG-TIA/3CH-AWG-TIA.kicad_sch
renames:
  Role:
    OLD_ROLE_A: NEW_ROLE_A
  Cluster:
    Old_Cluster_Name: New_Cluster_Name
```

Меняет значение везде, где оно СЕЙЧАС встречается, по всей иерархии схемы — перечислять затронутые
refdes не нужно. Проще `set` в одном отношении: конфликт многократного инстанса тут в принципе
невозможен, поскольку во все совпадения всегда пишется одно и то же новое значение. `old_value`, не
совпавший нигде, репортится как **предупреждение**, не фатал — это с равной вероятностью безобидный
повторный запуск (переименование идемпотентно), как и опечатка.

`rename --also-profile <root.yaml>` дополнительно применяет ТУ ЖЕ карту `renames:` к YAML-файлам
профиля, достижимым через его `include:`-граф — ответ на вопрос «переименовать Role/Cluster на схеме
и подхватить это в уже расставленное дерево `profiles/*.yaml` без второго, дублирующего файла
переименований». Правятся только семантически верные поля: `Role` → `role:`/`anchor_role:`/
`net_from_role:`/`net_template_same_as_role:` и КЛЮЧИ словарей `refs:`/`nets:`; `Cluster` →
`cluster:`/`anchor_cluster:` и `name:` у `clone_placements:` (этот `name` и есть Cluster-тег, который
пишется на компоненты платы). Правка — точечная подстановка текста (комментарии/форматирование
сохраняются, `.bak` + самопроверка `yaml.safe_load`), никогда не parse→dump. Переименование — только
по точному совпадению значения, как и на стороне схемы: иерархический кластер-литерал вида
`Channel_1/sub` НЕ перепишется при переименовании `Channel_1` — посегментное/префиксное
переименование намеренно вне скоупа (см. `kicadstamp/config_rename.py`).

### Страховки

- **Dry-run по умолчанию** — `--write` обязателен, чтобы что-то тронуть.
- **`.bak` + самопроверка на каждый файл, независимо** — перед записью исходный текст копируется в
  `<file>.bak`; после подстановки результат перепарсивается через `sexpdata` как проверка. Если не
  парсится — файл восстанавливается из `.bak` и репортится как неудачный, остальные файлы в пачке
  всё равно обрабатываются.
- **Отказ при не-ASCII** (`--allow-non-ascii` для обхода) — страхует ровно тот класс
  опечатки-гомоглифа, из-за которого этот инструмент вообще появился (кириллическая «С» вместо
  латинской в значении `Role`).
- **Отказ при запущенном KiCad** (`--force-with-kicad-running` для обхода) — `.kicad_sch`, открытый
  в Eeschema, рискует получить правку, которая будет тихо затёрта следующим сохранением из KiCad.
- После `--write` обязательно **«Update PCB from Schematic» в pcbnew** — правка сама на плату не
  долетает.

## Таб fieldstool

`gui.fieldstool_window.MainWindow` встроен целиком первым правым табом в основной GUI
(`gui/docks/fieldstool_dock.py`, см. [раздел про таб fieldstool в
gui_ru.md](./gui_ru.md#таб-fieldstool)) и делит с ним общий `BoardConnection` и единый поллинг
2с/400мс — сам он соединение никогда не создаёт и не опрашивает (REQ-сокет kipy допускает ровно
один запрос в полёте; второй независимый таймер на том же соединении перемежал бы запросы). У этого
окна **больше нет собственного дерева компонентов** (удалено 01.08.2026 вместе с отдельным классом
`ComponentTreeDock`, который его предоставлял — выбрать target без живого выделения на плате можно
через собственное дерево компонентов основного GUI, см. ниже).

Разбивает workflow на две фазы с разными требованиями к KiCad, в соответствии с ограничением выше:

### 1. Staging (KiCad открыт)

- **Pick root sheet** — указывает инструменту на проект (тот же концепт `root_sheet:`, что у CLI).
  **Rescan** перепарсивает (явное действие, не автополлинг — схема меняется только когда кто-то
  сохраняет в Eeschema, не каждые пару секунд) в `self._components` — одна строка на refdes (общий
  многоинстансный блок разворачивается в одну строку на каждого участника; многоюнитовый refdes
  схлопывается в одну строку, помечается divergent, если его units расходятся по Role/Cluster —
  схема это допускает, ничего не гарантирует синхронность).
- **Выбор цели** — любой из двух способов, и оба сразу заполняют комбобоксы **Role**/**Cluster**
  ЭФФЕКТИВНЫМ текущим значением выбранных target'ов — значением с живой платы, если live-снапшот
  уже видел этот ref (2026-08-04: у цели, которую уже застейджили, но ещё не applied, новое значение
  есть только на плате; при повторном выборе раньше показывалось старое, досейджевое значение из
  схемы, приходилось «править вслепую» — Денис живьём: «прописал роли... но когда кликаю эти диоды,
  ...роль... не видно»), иначе — значением из распарсенной схемы; одинаковое у всех — заполняет,
  разное — очищает (не оставляет со старым значением). Под меткой цели появляется маленькая пометка,
  какой из выбранных ref'ов всё ещё расходится со схемой (тот же дифф, что показывает Pending
  changes), обновляется на каждом тике поллинга, а не только по повторному клику:
  - **Выделить что-то в самом KiCad** (в Eeschema ИЛИ в Pcbnew — общее соединение следит за
    выделением на PCB, а поскольку выделение на схеме и плате в KiCad кросс-пробируются, выделение
    со стороны схемы тоже сюда долетает).
  - Собственное [дерево компонентов](./gui_ru.md#дерево-компонентов) основного GUI в режиме
    **Not yet applied** читает `self._components` этого окна — отфильтрованные по `pending_refs`
    (2026-08-03: только ref'ы с реальным расхождением схема/плата прямо сейчас, чтобы компонент,
    у которого всё уже совпадает, не висел в списке «не применённых» вечно). Клик по **листу** (один
    refdes) или узлу-**группе** (сразу все refdes этой группы Role/Cluster, для переименования
    целой группы без перепечатывания refdes) там же, вместо живого выделения на плате. Клик зовёт
    напрямую собственные `_on_tree_leaf_picked()`/`_on_group_picked()` этого окна и разворачивает
    этот таб вперёд.
- **Stage** — пишет текущие значения формы Role/Cluster прямо на живой footprint(ы) цели, по IPC (тот
  же механизм, что уже используют **Clear all**/**Delete selected** в дереве компонентов основного
  GUI) — `.kicad_sch` пока не тронут. **Enter** в поле Role или Cluster делает то же самое, что клик
  по кнопке (2026-08-04, Денис: «долго Stage жать») — намеренно не по потере фокуса, потому что
  фокус теряется и просто кликом по другому компоненту, а это застейджило бы чужое или недописанное
  значение без явного запроса на запись. Отдельной очереди-стейджинга больше нет: то, что сейчас лежит
  на живой плате (через Stage, Clear all, Delete selected, простановку Cluster в PlacerDock — что
  угодно из этого) — уже и есть отложенное состояние (переработано 2026-08-03 — прежняя
  JSON-очередь могла разъехаться с платой, например Clear all писал на плату, но ничего не стейджил,
  и Apply оставался мёртвым без возможности применить стирание).
  Цель, у чьего footprint'а ещё нет нужного поля (Role и/или Cluster), пропускается вместо отката
  всей пачки (2026-08-04, тот же гвард `has_field`, что уже используют Clear all/Delete selected) —
  предупреждение называет конкретную цель и поле; см. [Ensure fields...](#2-apply-kicad-должен-быть-закрыт)
  или [Почему поле должно уже существовать на цели](#почему-поле-должно-уже-существовать-на-цели).

### 2. Apply (KiCad должен быть закрыт)

- **Pending changes** (`gui/docks/pending.py`, прилеплен табом к Log внизу главного окна) показывает
  текущий дифф: каждый refdes, чьи Role/Cluster на живой плате отличаются от последнего Rescan
  схемы — пересчитывается заново при каждом Rescan и на каждом тике поллинга (~2с), нигде не
  хранится, поэтому не может протухнуть относительно платы.
- Проверяет, не запущен ли KiCad — если да, показывает **инструкцию** («сохрани работу и закрой
  KiCad, потом снова жми Apply»). Никогда не автоматизируется (см. [Почему эта зона записи остаётся
  отдельной](#почему-эта-зона-записи-остаётся-отдельной-от-kicadstampgui)).
- Если KiCad закрыт: прогоняет текущий дифф через тот же самый офлайн-пайплайн, что использует
  `fieldstool_cli.py set`, показывает сводку для подтверждения, затем пишет (те же страховки
  `.bak`/самопроверка, что у CLI). При успехе схема перечитывается — раз она теперь совпадает с
  платой, дифф выходит пустым и Apply снова выключается. Диалог успеха напоминает переоткрыть
  KiCad — запущенный процесс никогда не подхватывает изменённый снаружи файл схемы сам.
- **Ensure fields...** (тот же док, рядом с Apply) — отдельная проверка для другой проблемы:
  2026-08-04 живьём обнаружилось, что у одного компонента (`FB3`) в схеме было свойство `Role`, но
  свойства `Cluster` не было вообще — это не Clear all/Stage постарались (они пишут только в живую
  **плату** по IPC, `.kicad_sch` вообще не трогают, а отсутствующее поле там — жёсткая ошибка, а не
  тихое создание — см. [Почему поле должно уже существовать на цели](#почему-поле-должно-уже-существовать-на-цели)
  ниже). Ensure fields проходит по всему дереву схемы и добавляет пустое свойство `Role`/`Cluster`
  каждому компоненту, у которого его нет вообще, не трогая ни одно уже существующее значение (даже
  пустое). Те же гейт «KiCad закрыт», сводка для подтверждения и запись с `.bak`/самопроверкой, что
  у Apply — после этого нужно переоткрыть KiCad и самому запустить **Update PCB from Schematic**
  (F8), чтобы подтянуть новые поля на footprint'ы; сам этот пункт платы не касается.

## Почему поле должно уже существовать на цели

`kicadstamp.kicad.adapter.set_field_value()` (через него идёт живая запись на плату у Stage/Clear
all/Delete selected/тегирования Cluster в PlacerDock) — фатальная ошибка, если у footprint'а нет
поля с таким именем вообще: он никогда не создаёт поле с нуля, потому что для нового поля на живом
footprint'е платы нет разумного значения по умолчанию для позиции/слоя/синхронизации с символом в
схеме. Если видишь `FATAL ERROR: cannot set field 'Cluster'` — у этого refdes на footprint'е
реально нет такого поля: запусти **Ensure fields...** выше (или добавь один раз вручную, в Symbol
Properties или прямо в библиотечном символе) и **Update PCB from Schematic** (F8), прежде чем
пробовать снова.

дублирующимся) — та же основная логика (парсинг, точечная запись, страховки), просто реорганизована
в переиспользуемую библиотеку плюс режим `rename`, которого там не было. `root_sheet:` (обход
иерархии) заменяет `schematic_dir:` (плоский glob) — **не обратно совместимо**, старые конфиги
нужно обновить.
