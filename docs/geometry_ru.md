# `kicadstamp/geometry` – Геометрические утилиты

## Назначение

Модули в директории `geometry/` предоставляют низкоуровневые геометрические функции и классы, используемые для расчёта позиций компонентов, via и дорожек (tracks), получения собственной области пада (инвариантной к повороту), построения ограничивающих областей (keepout), поиска свободного места, предсказания положения падов после перемещения/поворота, генерации сетки термовиа и преобразования локальных координат шаблонов в глобальные.

Эти модули **не зависят** от KiCad и адаптера – они оперируют только координатами и векторами, что делает их легко тестируемыми и переиспользуемыми. Они используются в основном в `placement/services/manual_position_calculator.py`, `placement/services/clone_position_calculator.py`, `via_planner.py` и других модулях расстановки.

```
└── thermal_grid.py         # Генерация сетки термовиа
```

## Модули и их функции

### `keepout.py` – Ограничивающие области и поиск свободного места

**Назначение:**
Определяет класс `Rect` (выровненный по осям прямоугольник) и предоставляет функции для построения keepout-областей из bounding box'ов, проверки точки на занятость (с учётом радиуса via) и поиска свободного места вокруг идеальной позиции (по спирали или вдоль прямой).

**Препятствия СМЕШАННЫЕ** (с 2026‑09‑15): `Rect` (оси платы — габарит KiCad или via, запланированная ранее в этом же прогоне) и `PadArea` (`pad_area.py` — медь самого пада в ОСЯХ ПАДА) отвечают на **один** предикат `blocks_via(point, radius)`. Поэтому keepout, собранный из собственных областей падов, не наследует дефекты габарита при повороте, а поведение `Rect` остаётся бит в бит прежним.

**Ключевые классы и функции:**

| Имя | Описание |
|-----|----------|
| `Rect` | AABB-прямоугольник. Конструктор: `Rect(min_x, min_y, max_x, max_y)`. Методы: `from_bbox(bbox, clearance)` – создаёт прямоугольник из `Box2` с запасом; `from_circle(center, radius)` – аппроксимирует окружность квадратом; `intersects(other)` – проверяет пересечение; `blocks_via(point, radius)` – задевает ли меня via такого радиуса (историческая проверка «квадратной via», без изменений). |
| `point_is_clear(point, via_radius, keepout)` | Проверяет, свободна ли точка — ни одно препятствие из `keepout` не отвечает `blocks_via`. `keepout` — смешанный список из `Rect` и `PadArea`. |
| `build_keepout(bboxes, clearance_mm, mm_per_unit)` | Принимает список `Box2` (от адаптера) и строит список `Rect` с зазором `clearance_mm` с каждой стороны. Пропускает `None`-элементы. Оставлен для тех, у кого на руках только габариты; паду, который умеет построить свою область, лучше подходит `pad_area.pad_area_of`. |
| `find_free_point(ideal, keepout, via_radius, preferred_direction=None, step_mm=0.1, max_radius_mm=3.0, n_directions=8)` | Ищет ближайшую свободную точку вокруг `ideal` расширяющимися кольцами. На каждом кольце сперва пробуется `preferred_direction` (если задано), затем `n_directions` точек равномерно по кругу. Возвращает `Vector2` или `None`. Принимает тот же смешанный список препятствий. |
| `find_free_point_along_line(ideal, keepout, via_radius, line_direction, step_mm=0.1, max_radius_mm=3.0)` | Ищет свободную точку вдоль прямой, проходящей через `ideal`, с направлением `line_direction` (единичный вектор). Проверяет `ideal`, затем отступает в обе стороны с шагом. Тот же смешанный список. |

**Используется в:** `via_planner.py` **только** для поиска места под термовиа (единственный случай, где требуется автоматический поиск). Для всех остальных via (спицевых и компонентных) поиск не применяется – они размещаются строго по координатам шаблона.

### `pad_area.py` – Своя область пада

**Назначение:**
Превращает поля УЖЕ ПРОЧИТАННОГО пада в его собственную область меди — прямоугольник в **осях самого пада**. Keepout, замыкание выборки Extract и привязка межузловой меди спрашивают «точка на этом паде?», и выровненный по осям габарит KiCad отвечает на этот вопрос неверно для повёрнутого пада.

Две измеренные причины (15.09.2026, KiCad 10.0.6 + kipy 10.0.1, `profiles/3ch-awg-tia-v103`, IC2 под 315°): габарит — это AABB вокруг **повёрнутого** прямоугольника, поэтому сигнальный пад 0.300 × 0.850 мм читается как 0.813 × 0.813 мм (в 2.6 раза больше меди), и одна и та же медь может читаться «занято» при 45° и «свободно» при 0°; а при угле корпуса, не кратном 90°, габарит был измерен **сдвинутым** на один и тот же вектор для всех падов корпуса (1.724 мм в сессии Дениса — об этом предупреждает Лог; поворот через IPC на тестовой плате Linux этого не воспроизвёл, а зонд печатает число по каждому паду). Модуль **не читает плату**: все входы — поля уже прочитанного пада (`position`, `size`, `shape`, `offset`, `trapezoid_delta`, `angle_rad`), поэтому построение области не стоит ни одного IPC-запроса.

**Ключевые функции:**

| Имя | Описание |
|-----|----------|
| `PadArea` | Неизменяемое значение: `center` (нм — `position` + собственный `offset` пада, повёрнутый на угол пада), `half_w`, `half_h` (нм) и `angle_deg` (**абсолютный** угол пада, поворот корпуса уже включён). Методы: `contains(point, margin=0)` — точка переводится в оси пада и сравнивается там; `blocks_via(point, radius)` — та же консервативная проверка «квадратного угла via», что делал `Rect`, но в осях пада, поэтому она инвариантна к повороту корпуса; `inflated(margin)` — увеличенная копия (зазор остаётся «на сторону», как было у `Rect.from_bbox`); `bounds()` — выровненный по осям платы габарит для тех, кому нужен именно AABB. |
| `pad_area_of(pad)` | Своя область пада либо `None`, когда вызывающий обязан взять габарит KiCad: форма `custom`/`unknown` или падстек без пригодного `size`. Формы `rect`, `roundrect`, `chamfered`, `oval`, `circle` ограничены прямоугольником `size`; `trapezoid` раздувает оба полуразмера на `max(|delta.x|, |delta.y|)` — намеренно консервативно при любом толковании осей delta. Двойник пада, у которого атрибута `shape` нет вообще, читается как прямоугольник без смещения. |
| `pad_angle_deg(pad)` | Абсолютный угол пада в градусах — в DTO проект держит радианы, а примитив поворота берёт градусы, поэтому перевод живёт здесь. |
| `pad_shape_center(pad)` | Центр **формы** пада — на нём обязана центрироваться сетка термовиа, а не на отверстии. |
| `warn_bbox_fallback(logger, ref, pad)` | Пишет в Лог (с ref и номером пада), что пад без своей области будет измерен габаритом KiCad, — и только когда угол пада НЕ кратен 90°, то есть в единственном случае, где этот габарит был измерен сдвинутым. |

**Используется в:** `via_planner._build_keepout` (препятствия keepout), `thermal_grid.compute_thermal_via_grid` (центр сетки) и `template_selection._inflated_boxes` (шов, общий для замыкания Extract и `internode_copper.find_copper_units`).

### `pad_projection.py` – Предсказание позиции пада

**Назначение:**  
Предсказывает абсолютную позицию конкретного пада компонента, если компонент будет перемещён в новое место и повёрнут на заданный угол (с учётом возможного зеркалирования при флипе на обратную сторону). Логика централизована в этом модуле, чтобы избежать дублирования в разных частях проекта.

**Ключевые функции:**

| Имя | Описание |
|-----|----------|
| `local_pad_offset(fp, pad)` | Возвращает смещение пада относительно центра футпринта в **неповёрнутой** локальной системе координат (постоянная геометрия). |
| `predict_pad_position(fp, pad, dest, angle_deg, needs_flip)` | Предсказывает абсолютную позицию пада после перемещения футпринта в `dest` и поворота на `angle_deg` с учётом зеркалирования локального X при `needs_flip=True`. |

**Используется в:**  
В текущей версии KiCadStamp эта функция **не используется** в основном коде, так как все via (включая GND via) вычисляются исключительно по геометрии шаблона, без обращения к живой плате. Однако модуль оставлен для диагностических скриптов (например, `test_pad_mirror_convention.py`) и для возможного использования в будущем (например, для ручной корректировки позиций или проверки коллизий).

### `spoke_layout.py` – Преобразование для ManualSpoke

**Назначение:**  
Преобразует локальные координаты шаблона спицы (`along`, `across`) в абсолютные координаты платы для `ManualSpoke` (привязка к паду IC) с учётом сдвига `(shift_x, shift_y)` и поворота `rotation_deg` конкретной спицы. Также вычисляет итоговый угол поворота компонента и генерирует все via (как на уровне спицы, так и на уровне компонента) в виде `ResolvedVia` с абсолютными координатами и цепью (если `net` не указан, используется `rule.net`).

**Важно:** `ManualSpoke` также генерирует треки (`TemplateTrack` уровня спицы), так же как и `ClonePlacement`. Трек с `net = None` наследует `chain.net` — та же конвенция, что и у `TemplateVia` — именно это позволяет одному шаблону (например, `cap_pair_standard`) переиспользоваться в цепях с разными цепями без литерала цепи в самом шаблоне.

**Ключевые классы и функции:**

| Имя | Описание |
|-----|----------|
| `rotate_local_offset(along_mm, across_mm, rotation_deg)` | Поворачивает локальный вектор `(along, across)` на заданный угол вокруг нуля (без переноса). |
| `local_to_absolute(origin, along_mm, across_mm, rotation_deg)` | Преобразует локальный вектор в абсолютную позицию относительно `origin` с учётом поворота. |
| `ResolvedVia` | Полностью разрешённая via: абсолютная позиция, цепь, параметры отверстия. |
| `ResolvedTrack` | Полностью разрешённый отрезок дорожки: начальная и конечная точки (абсолютные), ширина, цепь, абсолютный слой. Используется и `ManualSpoke`, и `ClonePlacement`. |
| `ComponentLayout` | Структура, описывающая размещение одного компонента: ref, роль, позиция, угол, список via. |
| `SpokeLayout` | Структура, описывающая все элементы спицы: origin, список via (уровня спицы), список компонентов, список треков. |
| `apply_spoke_geometry(pad_position, spoke, template, rule_net, role_to_ref)` | Основная функция – принимает позицию пада FPGA, данные спицы (`ManualSpoke`), шаблон (`SpokeTemplate`), цепь правила и сопоставление роль→ref. Возвращает `SpokeLayout` с абсолютными координатами всех элементов, включая разрешённые треки. |

**Используется в:** `manual_position_calculator.py` для расчёта позиций компонентов и via.

### `clone_geometry.py` – Преобразование для ClonePlacement

**Назначение:**  
Аналог `spoke_layout.py`, но для `ClonePlacement` (клонируемых размещений). Отличия:
- `origin` может быть задан абсолютными координатами `(origin_x_mm, origin_y_mm)` или как сдвиг от якоря (если задан `anchor_ref` или `anchor_role`).
- `net` каждой via и трека **резолвится через** `net_resolution.resolve_net()` с учётом `params` и `net_overrides` (нет дефолтной `rule_net`). Если `net` не задан – фатальная ошибка, так как нет разумного дефолта.
- Поддерживается привязка к якорному компоненту/паду через `anchor_ref`/`anchor_role` и `anchor_pad`.
- Поддерживается **зеркалирование** (`mirror=True`) – вся конструкция отражается по оси X, углы компонентов пересчитываются по формуле `180°−φ`; меняется местами только внешняя пара медных слоёв (`F.Cu` ↔ `B.Cu`), а медь на **внутреннем** слое остаётся на своём слое (`utils/layers.mirror_layer` — внутренний слой принадлежит ПЛАТЕ, а не стороне конструкции).
- **Поддерживаются треки** – они преобразуются так же, как via и компоненты, с наследованием слоя от шаблона (если не задан явно).

**Ключевые классы и функции:**

| Имя | Описание |
|-----|----------|
| `_resolve_clone_via(origin, via, rotation_deg, clone, mirror)` | Преобразует `TemplateVia` в `ResolvedVia` с использованием `resolve_net` для цепи. Учитывает `mirror`. |
| `_resolve_clone_track(origin, track, rotation_deg, clone, tpl_layer, mirror)` | Преобразует `TemplateTrack` в `ResolvedTrack` с использованием `resolve_net` для цепи. Учитывает `mirror` и наследование слоя. |
| `_mirror_x(origin, p)` | X-зеркало точки относительно вертикальной оси через `origin`. |
| `apply_clone_geometry(clone, template, role_to_ref, anchor_position=None, mirror=False)` | Принимает `ClonePlacement`, шаблон и сопоставление роль→ref, а также опциональную абсолютную позицию якоря (если задан). Возвращает `SpokeLayout` с абсолютными координатами всех элементов (включая треки). |

**Используется в:** `clone_position_calculator.py` для расчёта позиций компонентов, via и треков для клонируемых секций.

### `thermal_grid.py` – Генерация сетки термовиа

**Назначение:**  
Вычисляет абсолютные координаты для массива термовиа под термопадом компонента (например, `IC1`). Учитывает размер пада, отступы от края, количество строк/столбцов и возможность шахматного порядка (stagger).

Локальная сетка (строки/столбцы/stagger/margin) раскладывается в **осях самого пада** и затем поворачивается на АБСОЛЮТНЫЙ угол пада примитивом проекта — `rotate_local_offset` (`spoke_layout.py`), та же формула y‑down, что у `cell_frame.rotate_ydown_mm`. Встроенное `x·cos − y·sin, x·sin + y·cos`, которое это заменило, крутило массив в ДРУГУЮ сторону: не видно, пока сетка переходит в себя (несмещённая при 0/90/180/270°, квадратная ещё и при 45°), и видно у `staggered` при 90°/270° или у прямоугольной при 45°. Центр сетки — центр **формы** пада (`pad_area.pad_shape_center`): `position` плюс собственный offset пада, повёрнутый, — но никогда не отверстие: у пада со смещением медь не там. Пад без позиции — фатал, а не сетка вокруг начала координат.

**Ключевые функции:**

| Имя | Описание |
|-----|----------|
| `get_pad_size(pad)` | Возвращает размеры медного слоя пада `(width, height)` в нанометрах. Бросает `GeometryError`, если медные слои отсутствуют. |
| `compute_thermal_via_grid(pad, rows, cols, margin_mm, stagger=False)` | Генерирует список абсолютных позиций для via, размещённых равномерно внутри площадки с учётом отступов `margin_mm`. Параметр `stagger` включает шахматный порядок. Возвращает список `Vector2`. |

**Используется в:** `via_planner.py` для планирования термовиа.

## Примеры использования

### 1. Построение keepout и поиск свободной точки (для термовиа)

```python
from kicadstamp.geometry.keepout import Rect, find_free_point
from kicadstamp.geometry.pad_area import pad_area_of
from kicadstamp.domain.geometry import Vector2

pads = adapter.get_footprint_pads(fp)              # пады уже прочитаны
clearance = int(0.2 * MM)

# Препятствия: у кого есть своя область — своя область (ноль IPC и корректность
# при любом повороте корпуса), у кого нет — габарит KiCad, одним пакетом.
keepout = []
for pad in pads:
    area = pad_area_of(pad)
    if area is not None:
        keepout.append(area.inflated(clearance))
fallback = [p for p in pads if pad_area_of(p) is None]
for bbox in adapter.get_bounding_boxes(fallback):
    if bbox is not None:
        keepout.append(Rect.from_bbox(bbox, clearance))

ideal = Vector2.from_xy(10_000_000, 20_000_000)
via_radius = 0.25 * MM  # 0.25 мм в нанометрах

free_point = find_free_point(ideal, keepout, via_radius, preferred_direction=(1, 0))
if free_point is None:
    print("Не удалось найти свободное место")
else:
    print(f"Свободная точка: ({free_point.x/MM:.3f}, {free_point.y/MM:.3f}) мм")
```

### 2. Генерация сетки термовиа

```python
from kicadstamp.geometry.thermal_grid import compute_thermal_via_grid
from kicadstamp.kicad.adapter import KiCadBoardAdapter

adapter = KiCadBoardAdapter()
adapter.refresh_board()
fp = adapter.get_footprint("IC1")
pad = adapter.get_pad_by_number(fp, "145")

points = compute_thermal_via_grid(pad, rows=4, cols=4, margin_mm=0.5, stagger=False)
for p in points:
    print(f"Via at ({p.x/MM:.3f}, {p.y/MM:.3f}) мм")
```

### 3. Преобразование шаблона для клонирования (с треками и mirror)

```python
from kicadstamp.geometry.clone_geometry import apply_clone_geometry
from kicadstamp.config import load_config

cfg = load_config("config.sexp")
template = cfg.templates["pi_filter_4"]
clone = cfg.clone_placements[0]
role_to_ref = {"PI_FILTER_C1": "C601", "PI_FILTER_FB": "FB601"}

# Без зеркалирования
layout = apply_clone_geometry(clone, template, role_to_ref, mirror=False)
for via in layout.vias:
    print(f"Via: ({via.position.x/MM:.3f}, {via.position.y/MM:.3f}) мм, net={via.net}")
for track in layout.tracks:
    print(f"Track: ({track.start.x/MM:.3f}, {track.start.y/MM:.3f}) -> "
          f"({track.end.x/MM:.3f}, {track.end.y/MM:.3f}), net={track.net}")

# С зеркалированием (вся конструкция переворачивается на обратную сторону)
layout_mirrored = apply_clone_geometry(clone, template, role_to_ref, mirror=True)
# Углы компонентов пересчитаны по формуле 180°−φ; F.Cu/B.Cu меняются местами, медь на внутреннем слое остаётся на своём
```

## Примечания

- Все координаты и размеры ожидаются в **нанометрах**, если не указано иное (поля `_mm` принимают миллиметры и конвертируются с помощью `MM = 1_000_000` из `utils/units.py`).
- `find_free_point` и `find_free_point_along_line` сейчас используются **только** для термовиа – все остальные via размещаются строго по заданным координатам без поиска.
- Модули `spoke_layout.py` и `clone_geometry.py` полностью независимы от зоны и `boundary` – вся геометрия задаётся в локальной системе шаблона, что делает конфигурацию поворотоинвариантной и предсказуемой.
- Для `ClonePlacement` цепи via и треков **обязательно** должны быть заданы (либо через `net` в шаблоне, либо через `nets`/`net_overrides` в клоне), так как нет `rule.net` по умолчанию. В противном случае выбрасывается `ValidationError`.
- Модуль `pad_projection.py` сохраняется для диагностических целей и возможных будущих расширений, хотя в основном потоке не используется.
- **Треки поддерживаются только в `ClonePlacement`.** В `ManualSpoke` треки не планируются (это архитектурное решение).

## Тестирование

Геометрические модули покрыты модульными тестами (в `tests/test_*.py`), которые проверяют:
- Корректность преобразования локальных координат в абсолютные.
- Построение keepout и поиск свободных точек.
- Генерацию сетки термовиа.
- Предсказание позиции пада (включая эмпирическую проверку конвенции зеркалирования).
- Преобразование треков в `clone_geometry.py` (поворот, зеркалирование, наследование слоя).

Для ручной проверки конвенции зеркалирования используется диагностический скрипт `test_pad_mirror_convention.py`, который выполняет реальный флип и поворот компонента в KiCad и сравнивает предсказания с фактическим положением пада.
