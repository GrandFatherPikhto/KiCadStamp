# `tests/` – Модульные и интеграционные тесты KiCadStamp

## Назначение

Директория `tests/` содержит три ВИДА тестов, и каждый тест несёт ровно один из
трёх маркеров, которые и говорят, какой это вид — `gui` / `integration` / `unit`.
Маркер ставится по ПУТИ, а не руками (см. [Запуск тестов](#запуск-тестов)):

1. **Модульные тесты** (`unit`) — ни окна Qt, ни KiCad: чистый Python плюс дубли.
   Геометрия, конфигурация, валидация, реестр, извлечение шаблонов, разрешение
   цепей, клонирование, слой s-expr. Быстрые, детерминированные, идут в CI.

2. **GUI-тесты** (`gui`, всё под `tests/gui/`) — нужна Qt-приложение (offscreen) и
   фикстуры окна/доков, KiCad всё ещё не нужен: доки, хаб, воркер, оверлей,
   настройки.

3. **Интеграционные тесты** (`integration`, `tests/integration_tests/`) — нужен
   ЗАПУЩЕННЫЙ KiCad с активной платой и её IPC-сокетом: подключение, создание
   via/треков, перемещение/флип, реестр, извлечение из выделения. Из CI они
   исключены намеренно (`pytest.ini` это проговаривает, и команда CI повторяет).

Один набор тестов, один `pytest.ini`, один общий сброс. Маркеры нужны, чтобы
команда могла НАЗВАТЬ, что именно она покрывает, а не выводить это из папки.

## Структура

Пять групп — по тому, ЧТО тесту нужно:

* `tests/conftest.py` — два autouse-сброса (состояние процесса, затем логи),
  хук маркеров, `records_from` и принудительно-английский вызов `setup_i18n()`,
  который выполняется на этапе сбора, до импорта пакета любым тест-модулем (поэтому
  английское утверждение безопасно даже на машине с русской локалью);
* `tests/fakes/` — общие дубли, которые ИМПОРТИРУЮТ, а не переопределяют, плюс
  клетка соответствия, пришпиливающая каждый дубль к реальному интерфейсу;
* `tests/gui/` — нужна Qt (offscreen);
* `tests/integration_tests/` — нужен ЗАПУЩЕННЫЙ KiCad с живой платой;
* `tests/test_*.py` — чистый Python.

Ф2 разбора тестов разложит плоский `tests/*.py` по доменным подпакетам в зеркало
`kicadstamp/`; маркеры и правила выше этот переезд переживают.

Список ниже СОКРАЩЁН намеренно: это ядро эпохи Ф0 (41 модуль), тогда как четыре
группы теперь держат 321 `.py`-файл всего (тест-модули плюс файлы `conftest.py`).
Каждое названное в нём имя всё ещё существует; но список — НЕ указатель: указатель
— это `ls tests/`, а Ф2 перегенерирует этот блок вместе с двумя таблицами описаний
ниже. Не сокращено другое — правило о том, куда класть НОВЫЙ тест: оно живёт в
[Расширение тестов](#расширение-тестов).

## Фикстуры

### Общие сбросы (каждый тест, любого вида)

В `tests/conftest.py` живут ДВЕ autouse-фикстуры.
`_reset_process_singletons` возвращает процессное изменяемое состояние на место
до И после каждого теста: рабочее множество конфига (слушатели, содержимое,
`enabled`), кэши `file_cache`, кэш пробы формата, кэш подсказок s-expr и состояние
двери `gui.connection` (предикат, проба, режим отказа, память «один раз на
площадку», глубина подписи). Она есть потому, что изоляция раньше копировалась по
файлам, а копии расходились — вторая копия этого сброса в тестовом файле теперь
ДЕФЕКТ, а не предосторожность (именно её носил `tests/gui/conftest.py` и больше не
носит).
`_reset_logging_after_test` работает только на teardown и останавливает
СЛУШАТЕЛЬ логов, который тест упустил; о ней — вместе с `records_from` ниже,
потому что обе существуют ради одного: тест не должен ничего решать по тому, что
оставил работать СОСЕД.

### Логи: `records_from(logger_name)`

Рецепты, судящие строку Лога ПО УРОВНЮ, идут через эту фикстуру, а не через
`caplog.records`:

```python
warnings = [r for r in records_from("kicadstamp.kicad.adapter")
            if r.levelno >= logging.WARNING]
```

caplog навешивает свой обработчик на КОРНЕВОЙ логгер, поэтому сырой список держит
все записи теста — из любого модуля и любой НИТИ. Клетка, судящая по уровню по
всему этому списку, зависит от того, что залогировал остальной процесс: соседний
тест бросает сокет, фоновая нить пишет WARNING pynng «Socket.close() did not
return», и клетка падает на чужой записи (измерено на прогоне в обратном порядке —
ради этого фикстура и появилась). Берите то же имя логгера, которое клетка уже
передаёт в `caplog.at_level(logger=...)`.

`_reset_logging_after_test` останавливает слушатель, который тест упустил, и
отсоединяет его queue-обработчик, чтобы GUI-клетки, ждущие
`get_log_listener() is None`, не были отравлены CLI-шными.

### Для интеграционных тестов (в `integration_tests/conftest.py`)

Созданы следующие фикстуры для работы с реальным KiCad:

| Фикстура | Область | Описание |
|----------|---------|----------|
| `adapter` | `session` | Один экземпляр `KiCadBoardAdapter` на всю сессию. |
| `board` | `session` | Доска из адаптера. |
| `test_config` | `session` | Загруженный тестовый конфиг из `kicadstamp_templates_example.sexp`. |
| `test_component_ref` | `function` | Refdes компонента для тестов (по умолчанию `C5`). |
| `test_pad_number` | `function` | Номер пада для тестов (по умолчанию `17`). |
| `temp_via` | `function` | Создаёт временную via на GND, удаляет после теста. Возвращает `(via_id, position, net)`. |
| `moved_component` | `function` | Перемещает компонент на 1 мм вправо, возвращает обратно после теста. Возвращает `(ref, original_pos, new_pos)`. |
| `flipped_component` | `function` | Переворачивает компонент на другую сторону, возвращает обратно. Возвращает `(ref, original_layer, target_layer)`. |
| `registry` | `function` | Создаёт временный реестр расстановки в `tmp_path`. |
| `template_extraction` | `function` | Обёртка над `extract_template_from_selection` (для тестов выделения). |

Эти фикстуры обеспечивают изоляцию тестов и автоматическую очистку (удаление via, восстановление позиций и слоёв) после каждого теста.

## Запуск тестов

### Команда CI — эталонный прогон

```bash
python -m pytest --ignore=tests/integration_tests -m "not integration" -q
```

Запускайте её в виртуальном окружении проекта (`source .venv/bin/activate`; как
это делается — в README): `python` там — интерпретатор venv, а на голой машине
может быть только `python3`.

Именно эту команду проект считает эталонной: её гоняет CI, и ей же измеряется
утверждение «тестов проходит больше, чем раньше».

**Никогда не запускайте голый `pytest`.** Он не просто ПРОПУСКАЕТ интеграционные
клетки — он их ЗАПУСКАЕТ: `testpaths = tests`, поэтому голый `pytest` собирает и
`tests/integration_tests/`. Без KiCad они осыпаются ошибками (kipy `ConnectionError`,
платы нет) — и это безобидно; с ОТКРЫТЫМ KiCad на реальной плате они ПИШУТ В ЖИВУЮ
ПЛАТУ. Поэтому падение голого прогона — не «известный шум окружения», от которого
отмахиваются, а признак того, что запустили прогон, который запускать не следовало.
Интеграционные клетки запускаются только НАМЕРЕННО: на тестовой плате, сохранив её,
как сказано в разделе ниже.

### Три вида по имени

Маркер и так исключает интеграционные, поэтому `--ignore` выше — вторая подтяжка,
и два написания собирают ОДНИ И ТЕ ЖЕ клетки:

```bash
python -m pytest -m unit -q            # чистый Python, ни Qt, ни KiCad
python -m pytest -m gui -q             # Qt, offscreen
python -m pytest -m integration -q     # ПИШЕТ В ЖИВУЮ ПЛАТУ — только намеренно
```

Третья строка — единственная в этом документе команда, которая трогает железо:
никогда не тянитесь к ней просто так — на тестовой плате, сохранив её, и прочитав
предупреждение выше.

Один файл или одна клетка:

```bash
python -m pytest tests/test_spoke_layout.py -q
python -m pytest tests/test_spoke_layout.py::test_local_to_global -q
```

### Прогон в обратном порядке

```bash
python -m pytest $(ls -r tests/test_*.py tests/gui/test_*.py) -m "not integration" -q
```

Независимость от порядка — это свойство, которое набор тестов обязан ДЕРЖАТЬ, а
не на которое надеются: общий сброс и хук маркеров и существуют затем, чтобы
клетка не зависела от того, что прошло до неё. Зелёный прямой прогон рядом с
красным обратным означает одно из двух, и само падение называет, какое:

* клетка судит ГЛОБАЛЬНОЕ состояние, которого не создавала, — форма класса A, где
  `caplog.records` читается ПО УРОВНЮ по всему корневому логгеру и вердикт решает
  запись соседа (измерено: WARNING про сокет pynng из фоновой нити). Лечится
  `records_from` (см. [Фикстуры](#фикстуры)).
* у клетки СВОЯ гонка — рабочая нить, которую она запускает и не дожидается
  (измерено: `threading.current_thread()` внутри `QThread` — это `_DummyThread`).

Оба случая были настоящими и оба починены; обратный прогон теперь часть приёмки, а
не диагностика, к которой тянутся задним числом.

### Тестовые плагины (обязательны — без них прогон не стартует)

Два тестовых плагина объявлены в `pytest.ini` в строке `required_plugins`
(`pytest-qt`, `pytest-timeout`), поэтому на копии без них прогон не идёт
ослабленным, а останавливается с `ERROR: Missing required plugins`:

- **pytest-qt** для GUI-тестов не опция. PyQt6 зовёт `qFatal()`, когда исключение
  выходит из Qt-слота, а `sys.excepthook` всё ещё обработчик по умолчанию, — это
  дамп ядра, `Fatal Python error: Aborted`, `EXIT=134`. Прогон пропадает целиком,
  и отчитались только те клетки, что успели пройти. pytest-qt подменяет хук на
  каждой фазе теста и превращает такое исключение в `FAILED`, называющий файл и
  строку отказа (для двери — ту строку, которую и надо править). `qt_api = pyqt6`
  выставлен намеренно: измерено поведение PyQt6, а на машине может оказаться и
  PySide6.
- **pytest-timeout** обязателен потому, что `timeout = 60` в `pytest.ini` без него
  не делает вообще ничего: зависший GUI-тест убьёт внешняя команда `timeout <N>`,
  и имя зависшего теста потеряется.

Ставятся через `pip install -e ".[dev]"`; те же пины лежат в `requirements.txt`,
который и устанавливает CI.

### Интеграционные тесты (с реальным KiCad)

**Важно:** перед запуском убедитесь, что:
- KiCad открыт и активна тестовая плата.
- Компоненты, используемые в тестах (например, `C5`), существуют на плате.
- Тесты не нарушают критичную разводку (они восстанавливают состояние).

```bash
# Все интеграционные тесты
pytest tests/integration_tests/ -v -m integration

# Конкретный файл
pytest tests/integration_tests/test_via_ops.py -v -m integration

# С отключением перехвата вывода для отладки
pytest tests/integration_tests/ -v -s -m integration
```

## Описание модульных тестов

Тоже СОКРАЩЕНО — то же ядро эпохи Ф0, поэтому читайте это как «что пинят эти
старые клетки», а не как карту покрытия. Тест, добавленный позже, описан своим

## Примечания

- **Модульные и GUI-тесты** KiCad не нужны: их запустит любая машина с
  установленным dev-extra, и CI гоняет их на Linux и Windows.
- **Интеграционные тесты** требуют открытого KiCad с платой и из CI исключены.
  Каталоги плат ЛОКАЛЬНЫ для машины и перечислены в `.gitignore` (`test_boards/` и
  `boards/**`), поэтому в свежей копии платы нет вообще — ровно поэтому голый
  `pytest` здесь и рапортует ошибками. Предпочитайте тестовую плату (например,
  `test_boards/10CL006YE144C8G.kicad_pcb`) рабочему проекту; фикстуры
  восстанавливают плату, но всё равно запускайте на копии или после сохранения.
- Три маркера разбивают сбор ровно: `gui` + `unit` + `integration` = всё, и
  `tests/test_marker_contract.py` падает, если разбиение перестанет быть
  разбиением (или если какой-то вид перестанет помечаться).

## Расширение тестов

**Куда класть новый тест** — по тому, что ему нужно; маркер идёт за путём:

* чистая логика → `tests/test_<module>.py` (маркер `unit`);
* док, окно, виджет → `tests/gui/` (маркер `gui`);
* живой KiCad → `tests/integration_tests/` плюс `@pytest.mark.integration` (путь
  уже помечает его; декоратор — ремень к подтяжкам пути).

**Куда класть новый ДУБЛЬ или ХЕЛПЕР:**

* дубль, нужный БОЛЬШЕ чем одному файлу → `tests/fakes/`, и добавьте для него
  клетку в `tests/test_fakes_conformance.py` (клетка пришпиливает дубль к
  реальному интерфейсу в обе стороны: он не должен выдумывать ничего, а имена,
  объявленные им как пробелы, должны действительно существовать на конкретном
  классе);
* дубль для ОДНОГО файла → в этот файл, с именем на подчёркивание (`_FakeBoard`) —
  в `tests/fakes/` лежит общее, и имя оттуда не должно переопределяться в
  тестовом файле;
* построитель (данные, текст, собранная плата) → в `tests/fakes/`, по назначению,
  а не в корень `tests/`: `schematic_text.py`, `overrides_store.py`,
  `live_board.py`;
* pytest-ФИКСТУРА → в `conftest.py` того уровня, которому она нужна.

**Четыре правила, которые новый тест не должен ломать** (их сторожит
`tests/test_repo_hygiene.py`, и каждый сторож громко падает, если его собственное
сканирование ослепнет):

1. никаких `sys.path.insert` под `tests/` — `pythonpath = .` заменил все 120;
2. `kicadstamp` обязан разрешаться ВНУТРИ rootdir прогона (editable-установка из
   другой копии заставляет набор измерять код, который никто не правит);
3. имя, живущее в `tests/fakes/`, не должно определяться в тестовом файле второй
   раз;
4. никаких присваиваний атрибуту импортированного модуля или имени вне
   `monkeypatch` (немногие исключения перечислены там же, каждое с измеренной
   причиной, и список проверяется на гниение).

**Байтовые слепки: когда они законны.** Точные БАЙТЫ можно сравнивать только там,
где байты И ЕСТЬ предмет: s-expr-ПИСАТЕЛЬ (`test_sexp_config_roundtrip.py`),
хранимая фикстура или сторож версии формата. Везде ещё сравнивайте по СМЫСЛУ
(`sexp_to_dict` плюс нормализация `_strip_defaults`, которой пользуется сам слой
конфига) и говорите в комментарии, какое из двух делает клетка. Причина измерена,
а не стилистическая: Ф1.3 классифицировал все 84 байтовых утверждения набора — 26
смысловых, 7 честных писательских/шаблонных, 51 в файлах, которые байтов вообще не
касаются. Слепок значения, которое писатель никогда не производит, превращает
переименование в красный тест.

**Оснастки приёмки (мутационные проверки — не часть набора).**
`kicadstamp/diagnostics/claude_mutations_accept_*.py`: 13 оснасток, каждая вносит
одну именованную мутацию в продукт и сообщает, покраснел ли сторож
(`KILLED` / `SURVIVED` / `INVALID`). Запускайте их РУКАМИ, против копии, которая НЕ
то дерево, из которого они стартовали:

```bash
KICADSTAMP_ACCEPT_ROOT=<отдельная копия> \
KICADSTAMP_PYTHON="$PWD/.venv/bin/python" \
  "$PWD/.venv/bin/python" kicadstamp/diagnostics/<оснастка>.py
```

Две измеренные ловушки: если accept root равен текущему дереву, оснастка, чья
мутация — «внутренний прогон импортирует ГЛАВНУЮ копию», становится пустышкой и
рапортует SURVIVED; а строка INVALID («шаблон встречается 0 раз») означает, что
устарела МУТАЦИЯ, а не что набор силён. Планка «до Ф1» — 127 убитых / 7 выживших /
6 недействительных.
