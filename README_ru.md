# KiCadStamp v2.1.0

**KiCadStamp** — инструмент автоматизации размещения и клонирования блоков печатных плат в **KiCad 10**.
Подключается к запущенному KiCad по IPC API и делает повторяемым то, что иначе приходится делать руками
сотни раз: расставляет компоненты, ставит переходные отверстия, прокладывает дорожки и переносит целые
функциональные блоки с места на место.

Это **продвинутая альтернатива плагину KiCad Replicate Layout**, рассчитанная на сложные многоканальные
платы, иерархические схемы и повторное использование готовой трассировки: размножение участков платы,
копирование каналов, клонирование П-фильтров и цепей питания, перенос разводки между одинаковыми блоками.

Есть графический интерфейс (PyQt6), командная строка и MCP-сервер для работы из Claude Code.

Ключевая идея — **компоненты выбираются по ролям, а не по refdes**. Блок описывается один раз в локальных
координатах, а к плате привязывается через роли и цепи. Переаннотация схемы ничего не ломает.

---

## Что умеет

- **Ячейки (Cell)** — геометрия блока в локальных координатах: компоненты, via, дорожки. Ячейку можно
  повернуть, сдвинуть, отзеркалить и применить в любом месте платы.
- **Подбор по ролям** — вместо `C12`/`R7` пишутся роли (`PI_FILTER_C1`, `HEAVY`), а конкретные экземпляры
  берутся из пула по полю `Role` в схеме и по цепи.
- **Деревья размещения (`trees:`)** — где именно стоит каждый экземпляр. Узел дерева ссылается на entity
  и несёт позицию; сама entity позиции не имеет в принципе.
- **Клонирование секций** — по выделению (штучный экземпляр) или по цепям (многократно повторяющийся блок
  с параметризацией имён цепей).
- **Извлечение из платы** — выделил блок в KiCad, прочитал в ячейку, дальше применяешь куда угодно.
- **Реестр расстановки** — помнит UUID созданных via и дорожек, сверяется с живой платой, поэтому повторный
  прогон не плодит дубликаты и убирает устаревшее.
- **Предварительная валидация** — конфиг проверяется целиком до первой правки платы: существование ячеек,
  падов и якорей, хватает ли компонентов в пулах, уникальность имён, разрешимость цепей.
- **Откат** последней операции.
- **Работа со схемой** — массовая простановка и переименование полей `Role`/`Cluster` прямо в `.kicad_sch`
  (fieldstool), без IPC и с закрытым KiCad.
- **Файловый клонер** — разбор `.net` и `.kicad_pcb` без IPC, карта близнецов каналов для иерархических
  проектов.
- **Python API** — размещение можно не описывать в конфиге, а строить кодом: чтение платы через
  `kicadstamp.explore`, сборка размещения через `kicadstamp.author`.

DRC сознательно вне области задач: коллизии дорожек проверяет сам KiCad.

## Установка

### Требования

- **Python 3.10** или новее.
- **KiCad 10.0.4** или новее с включённым IPC API (*Preferences → Plugins → Enable IPC API server*).
- Для графического интерфейса — рабочий Qt-стек (ставится вместе с зависимостями).

### Установка

```bash
git clone <repo>
cd KiCadStamp
python -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install -e .
```

Зависимости ставятся автоматически и закреплены по версиям. Рабочие: `kicad-python==0.7.1`
(обёртка над KiCad IPC, импортируется как `kipy`), `PyQt6==6.11.0`, `sexpdata==1.0.2`,
`pynng==0.9.0`, `protobuf==5.29.6`.

Дополнительные наборы:

```bash
pip install -e ".[dev]"           # pytest, babel, pyflakes
pip install -e ".[diagnostics]"   # numpy, scipy, psutil, rich, watchdog
pip install -e ".[mcp]"           # mcp — только для MCP-сервера
```

### Точки входа

После установки доступны три команды:

| Команда | Что запускает |
|---|---|
| `kicadstamp` | интерфейс командной строки |
| `kicadstamp-gui` | графический интерфейс |
| `kicadstamp-mcp` | MCP-сервер (stdio) |

Из исходников без установки работают эквивалентные скрипты в корне репозитория:
`kicadstamp_cli.py`, `kicadstamp_gui.py`, `fieldstool_cli.py`.

## Быстрый старт

### 1. Настройка ролей в схеме (Eeschema)

Компонент участвует в размещении, только если у него есть пользовательское поле `Role`:

1. Откройте символ в Eeschema.
2. Добавьте поле с именем **Role** и значением, соответствующим роли в ячейке (например, `LIGHT`, `HEAVY`).
3. Выполните **Update PCB from Schematic**, чтобы поле попало на плату.
4. Проверьте, что поле читается: выделите компонент в KiCad и выполните
   ```bash
   python -m kicadstamp.diagnostics.get_selected_component
   ```
   Скрипт печатает refdes, значение, посадочное место, позицию, угол, пады, цепи и поле `Role`.

Проставлять роли десяткам компонентов вручную не нужно — для этого есть fieldstool
(вкладка в GUI или `fieldstool_cli.py`), см. [docs/fieldstool_ru.md](./docs/fieldstool_ru.md).

### 2. Запуск

```bash
kicadstamp-gui                          # графический интерфейс
kicadstamp apply --config profiles/my/config.sexp --dry-run
```

`--dry-run` печатает план, не трогая плату. Это правильный первый запуск на незнакомом конфиге.

## Ключевые понятия

Короткий словарь. Подробности — в [docs/config_ru.md](./docs/config_ru.md) и
[docs/placement_ru.md](./docs/placement_ru.md).

**Role** — поле компонента в схеме. Роль говорит, *чем* компонент работает в блоке, а не как он называется.

**Cluster** — второе поле компонента, группирующее экземпляры одного блока. Роль + кластер однозначно
указывают на компонент, не привязываясь к refdes.

**Cell (ячейка)** — описание блока в локальных координатах: компоненты по ролям, via, дорожки.
У ячейки **нет своего положения на плате** — это шаблон.

**Якорь ячейки** — точка ячейки, которой она «садится» на плату (`anchor_xy`/`anchor_role`/`anchor_pad`).
Задаётся в системе координат самой ячейки; при применении разрешается в живые координаты.

**Entity (сущность)** — всё о сущности, кроме того, где она стоит: какая ячейка, электрика,
идентичность. Полей позиции в entity нет в принципе.

**Tree (дерево размещения, `trees:`)** — где стоит. Узел дерева ссылается на entity и несёт координаты;
узлы вкладываются друг в друга, координаты потомка отсчитываются от родителя.

**ManualSpoke (спица)** — via с дорожкой от пада компонента, задаваемая вручную в цепочке (`chains:`).

**ClonePlacement** — исторический механизм размещения клона (по выделению или по цепям). Живой, но для
новых профилей предпочтительна модель Entity + Tree; мигрировать помогает `tools/convert_placements.py`.

**Scheme List** — снимок набора компонентов с платы, который можно перечитать и переразместить целиком.

**Реестр** — журнал созданных via и дорожек с их UUID. Обеспечивает идемпотентность: повторный прогон
обновляет, а не дублирует.

## Формат конфигурации

Конфиг — **s-expression** (`.sexp`), как и родные форматы KiCad. Файл с другим расширением отвергается
с фатальной ошибкой. (Читается ещё `.json` — на нём держится легаси-файл `scheme_lists.json`; теперь GUI
сам создаёт при первой записи Scheme List файл `scheme_lists.sexp`, а уже существующий `scheme_lists.json`
продолжает использоваться как есть.)

Профиль можно разбить на несколько файлов: `include:` в корне подключает другие `.sexp`/`.json`
рекурсивно, каждый может нести любую комбинацию секций. Команда `flatten` собирает такой граф обратно
в один самодостаточный файл.

Полный справочник с примерами из живого профиля — [docs/config_ru.md](./docs/config_ru.md).

## Команды CLI

| Команда | Назначение |
|---|---|
| `apply` | применить расстановку из конфига к открытой плате |
| `undo` | откатить последнюю операцию |
| `extract` | извлечь ячейку из текущего выделения на плате |
| `extract-net` | снять медь одной цепи (дорожки + via) в запись `net_traces:` |
| `clone-extract` | снимок канала в `.sexp` (файловый клонер, без IPC) |
| `clone-plan` | сгенерировать готовый блок `clone_placements:` для клона канала |
| `channel-copy` | скопировать размещение целого канала из одного в другой по карте близнецов |
| `flatten` | свернуть `include:`-граф в один самодостаточный файл |
| `convert-trees` | переписать `trees:` со снятой грамматики `own_anchor` на mount-узлы |

Полное описание флагов — [docs/commands_ru.md](./docs/commands_ru.md).

Пример:

```bash
kicadstamp apply --config profiles/my/config.sexp --dry-run   # только план
kicadstamp apply --config profiles/my/config.sexp             # применить
kicadstamp undo --verbose                                     # откатить
```

## Графический интерфейс

```bash
kicadstamp-gui [--timeout-ms 20000] [--verbose]
```

Основной способ работы с проектом. Слева три дерева — **Components** (компоненты платы и схемы),
**Config** (структура конфига) и **Trees** (деревья размещения); справа — контекстная панель, которая
следует за выбранным узлом; внизу — лог.

Правки не пишутся на диск сразу: они копятся в рабочем наборе, а **File → Save** коммитит всё разом.

Подробно — [docs/gui_ru.md](./docs/gui_ru.md), горячие клавиши — [docs/hotkeys_ru.md](./docs/hotkeys_ru.md).

## Python API

Размещение можно не описывать в конфиге, а **писать кодом** — две необязательные библиотеки поверх
того же конвейера, без своего формата и без обхода валидации.

`kicadstamp.explore` — чтение платы: `Board.select(role=..., cluster=..., sheet=..., net=...)` отвечает
на вопросы вида «какие компоненты несут `Role=AD_DAC`», «на какой цепи этот пад», «под каким листом
стоит этот футпринт» — вместо одноразового скрипта каждый раз.

`kicadstamp.author` — построение размещения: `ClonePlacement` и `Chain` это обычные датаклассы, их
можно собирать циклом с настоящими переменными Python вместо копипаста и подстановки плейсхолдеров.
Результат либо применяется сразу через `apply_config()`, либо сохраняется в файл, подключаемый
через `include:`.

```python
from kicadstamp.explore import Board

board = Board.connect(config_path="profiles/my/config.sexp")
for fp in board.select(role="AD_DAC"):
    print(fp.ref, fp.cluster, fp.sheet)
```

Подробно, с разбором реального скрипта — [docs/python_ru.md](./docs/python_ru.md).

## MCP-сервер

```bash
pip install -e ".[mcp]"
kicadstamp-mcp
```

Сервер по протоколу MCP через stdio: Claude Code и другие MCP-клиенты видят живую плату и могут с ней
работать — читать идентичность платы, футпринты с ролями и кластерами, текущее выделение и цепи;
применять конфиг через тот же проверяющий конвейер, что и `apply`; при явном разрешении — двигать
элементы напрямую.

## Диагностика и известные проблемы

### Крах KiCad на первой записи по IPC (#24966 / #25322) — исправлено в 10.0.7

При открытом редакторе схем **первая транзакция сессии** (`begin_commit()`/`push_commit()`, даже пустая)
могла уронить KiCad — null pointer в `API_HANDLER_EDITOR::checkForBusy`. Симптом со стороны клиента:
KiCad молча закрывается, приходит `ConnectionError: Error receiving reply from KiCad: Timed out`.

**Исправлено в апстриме** 2026-09-07 (Jon Evans, коммит
[`bdcb1509`](https://gitlab.com/kicad/code/kicad/-/commit/bdcb150903658e2c8f91b8862f87d950b35c0d1f)),
веха **10.0.7**. Оба тикета закрыты.

**На 10.0.6 и старше** обход прежний: перед первой записью закройте редактор схем. В коде остаются
предупреждение (`check_write_crash_risk`) и повторные попытки с задержкой — они безвредны и на
исправленных версиях просто не срабатывают. Уязвима была именно первая запись сессии: если первый
`apply` сделать при открытом только PCB Editor, открывать Schematic Editor после этого обычно
безопасно.

Полный разбор и инструменты охоты за крашами — [docs/crash_hunting_ru.md](./docs/crash_hunting_ru.md).

### Диагностические скрипты

В `kicadstamp/diagnostics/`:

- `diagnose_first_write_crash.py` — лесенка чтений и записи для локализации краха,
  см. [docs/diagnose_first_write_crash_ru.md](./docs/diagnose_first_write_crash_ru.md);
- `test_move_one_cap.py`, `test_flip_one_cap.py`, `test_create_one_via.py` — минимальные тесты операций;
- `test_pad_mirror_convention.py` — эмпирическая проверка зеркалирования падов при флипе;
- `get_selected_component.py` — подробности о выделенных компонентах, включая поле `Role`;
- `get_pad_bbox.py`, `diagnostic_keepout.py` — вспомогательные.

Обзор — [docs/diagnostics_ru.md](./docs/diagnostics_ru.md).

## Версионирование

Единый источник правды — `__version__` в [`kicadstamp/_version.py`](./kicadstamp/_version.py): заголовок
этого README и `--version`/`-V` у всех точек входа читают версию оттуда, а не хранят отдельный литерал.

Считаем по этапам, а не по коммитам: **MINOR** растёт на 1 за каждый заметный блок работы (одна сессия
рефакторинга — один шаг, сколько бы коммитов внутри ни было), **PATCH** — точечные фиксы между этапами,
**MAJOR** — только реальные breaking-изменения CLI или формата конфига (`.sexp`/`.json`).

**2.1.0** — чтение межузловой меди в дерево и полный медный стек (2026-09-12): единица «медь между
падами» читается с платы в плоский список `net_traces:` и выделяется на плате (и обратно — «чья эта
медь?»); медь ячеек и трасс может лежать на ЛЮБОМ медном слое (`F.Cu`, `In1.Cu`…`In30.Cu`, `B.Cu`) и
возвращается на свой слой, разбор имени строгий; при зеркалировании меняются местами только
`F.Cu`/`B.Cu`, а медь внутреннего слоя остаётся на своём слое.
Формат при этом **расширился**: старые конфиги читаются как читались, но конфиг с
`layer: In1.Cu` у дорожки, записанный этой версией, на 2.0.x **не загрузится** — поэтому
MINOR, а не PATCH.

**2.0.0** — переход на `.sexp` как единственный формат конфига (2026-08-28) и на модель Entity + Tree.
